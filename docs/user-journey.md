# 用户旅程

## 1. 按排查目标创建任务

首页是分析任务列表，展示任务名称、Agent / 版本、数据量、最新分析状态和进度。新建任务时输入名称（默认提供日期名称），Agent、版本与目标可选填。

上传 DeepAgent 或 OTel GenAI 轨迹文件，也可从轨迹库选择已有轨迹。上传后展示逐文件校验结果、识别条数、重复项和缺失的业务结果。错误文件可排除后继续，业务结果缺失时需要由用户补齐。上传和校验在本地完成。

在分析配置里选择诊断深度。低档用于初筛，中档使用双路综合，高档使用多路综合并提供额外的因果回溯供复核。各档位显示适用场景，单独运行引擎可在折叠区选择。校验通过后可保存草稿，或创建并开始分析。开始时保存本轮引擎模式、模型连接、参数和版本。

OTel 原始 span 与消息映射保留，原格式解析路径不变；输入适配继续共用官方 `to_unified` 与 schema。并发分支、截断历史或缺失消息继续由适配器明确提示，不补造轨迹。

## 2. 在任务内管理分析记录

任务详情包含轨迹列表、分析记录、数据与配置三个页签。概览分别统计业务结果、诊断完成 / 失败、逐条建议和人工复核。业务失败与模型请求失败是两种状态。

轨迹由后端筛选与分页，默认每页 10 条，可切换 20 / 50 条。翻页保留勾选，表头全选只作用于本页；更改筛选回到第一页并清空勾选。任务统计覆盖本轮全部数据，批量按钮与所选操作的范围分别标明。

“分析待处理”仅补齐尚未分析项；“重试失败”保留在本轮内，追加请求并保留失败阶段产物。已经完成的轨迹不会被所选诊断操作重复提交。“重新分析”使用同一数据范围创建新分析记录，不复用原作业；官方响应缓存规则不变。旧记录连同模型结论、建议和人工复核保持只读，也由后端校验禁止变更。

原有数据首次启动时归入历史任务，不自动启动模型。原配置不完整时明确标注已有报告与迁移配置的边界。

## 3. 核查证据

默认先看关键失败步骤和结论。点击步骤跳到左侧原文；再进入“错误实例”查看对象、初始触发、有效错误起点、修复与终局联系。终局相关筛选帮助聚焦候选，但最终裁决允许指向上游实例之外的步骤。

“触发证据”原样展示官方返回的错误承诺与被违反依据。原文引用支持原始消息跳转高亮；官方压缩视图引用可展开对应视图并高亮引用片段，通过“对照原文”查看对应消息。引用可定位到多个视图时保留位置选择；只有原始输入和官方视图都无法定位时才提示来源未定位。模型原始分类与解释保留原语言。

引用统计分别展示原文、压缩视图和未定位数量。来源定位只说明文字可追溯，不表示摘要含义或诊断因果已经人工确认。

同一轮次的详情可以切换查看本轮实际运行的各引擎结果。需要调整诊断深度时，在任务详情发起新一轮分析。

## 4. 人工复核与导出

确认、修改或驳回结论，并在复核说明中记录修复与验证计划。修改关键步骤时校验消息范围和诊断资格；驳回清空关键步骤。重新选择确认模型结论会恢复模型原始字段。

可在“改进建议”页签按需生成官方反馈，查看并复制改进指令、展开失败总结和替代候选。基于本次模型原始诊断，额外模型请求与用量独立显示；人工复核有改动时明确提示来源差异。生成失败可重试，不影响原诊断。原格式与 OTel GenAI 兼容，建议不会自动应用或被标记为已验证。

导出 Markdown（当前复核结论、模型原始结论、证据、生命周期、已生成建议与用量）、完整 JSON、官方最终原始 JSON，或独立的官方反馈 JSON。人工复核和建议均不覆盖原始诊断。

## 返回路径与持久化

单条详情保留任务与分析记录上下文。上一条 / 下一条遍历当前筛选范围，支持跨页；返回任务时保留筛选、每页条数与所在页，并标记当前轨迹。刷新后数据、请求历史与复核来自 SQLite，页码和筛选来自 URL。

从单条详情导出 Markdown、完整 JSON、官方最终输出或已生成反馈；从任务列表导出整轮或所选轨迹 JSON。导出保留每次请求、原始模型结果和人工记录。

没有任务时引导新建；未配置模型可先保存已校验数据为草稿。任务汇总根因类别与进度，不生成跨轨迹的综合优化指令。
