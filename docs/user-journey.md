# 用户旅程

## 1. 创建分析任务

首页是分析任务列表，展示任务名称、数据量、最新分析状态和进度。新建任务时输入名称，默认提供带日期的名称。Agent 由上传的轨迹识别。

分析任务列表和轨迹库支持勾选后批量删除。确认弹窗显示所选数量。系统删除符合条件的记录，并逐项说明未删除的原因。删除任务会保留库内轨迹。轨迹仍被任务引用时，需先删除引用它的任务。同批选中的失败模式分析任务会先处理，以解除对来源任务的引用。

上传 DeepAgent 或 OTel GenAI 轨迹文件，也可从轨迹库选择已有轨迹。上传后展示逐文件校验结果、识别条数、重复项和缺失的业务结果。错误文件可排除后继续，业务结果缺失时需要由用户补齐。上传和校验在本地完成。

在分析配置里选择诊断等级、诊断模型和提示词语言。Fast（快速诊断）适合日常 Badcase 和批量诊断。Standard（标准诊断）兼顾诊断深度和推理成本。Deep（深度诊断）通过多路交叉验证处理疑难问题和复杂长轨迹。对于业务失败的轨迹，至少两路完成后，系统根据各路结论和原文证据生成综合结论。模型列表会预选默认诊断模型，可切换至其他配置。校验通过后可保存草稿，或创建并开始分析。开始时保存本轮诊断等级、模型连接、参数和版本。

OTel 原始 span 与消息映射保留，原格式解析路径不变；输入适配继续共用官方 `to_unified` 与 schema。并发分支、截断历史或缺失消息继续由适配器明确提示，不补造轨迹。

## 2. 查看任务当前分析

任务详情展示当前分析，包括轨迹列表、任务改进建议、数据与配置。概览分别统计业务结果、诊断完成 / 失败、单条建议和人工复核。业务失败与模型请求失败是两种状态。轨迹列表和轨迹库中的「Agent」列展示从原始 span 识别的轨迹 Agent，支持按名称搜索。

可勾选的分页表格默认每页 10 条，可切换 20 / 50 条。「全选本页」只作用于当前页，「跨页全选」覆盖符合当前筛选条件的记录。再次点击已选中的全选框可取消对应范围的勾选。翻页保留勾选，更改筛选回到第一页并清空勾选。任务统计覆盖本轮全部数据，批量按钮与所选操作的范围分别标明。

「分析待处理」补齐尚未分析项。「重试失败」在当前分析追加请求，保留失败阶段产物。「重新分析」以同一批轨迹启动新诊断，任务页随之显示新的进度、结果和配置。本次诊断全部完成后，系统清理启用此功能后产生且已被替代的无引用结果。失败时保留原结果数据，可在当前任务重试失败项。已有历史数据与仍被旧报告引用的数据继续保留。

原有数据首次启动时归入历史任务，不自动启动模型。原配置不完整时明确标注已有报告与迁移配置的边界。

## 3. 核查证据

默认先看关键失败步骤和结论。点击步骤跳到左侧原文；再进入“错误实例”查看对象、初始触发、有效错误起点、修复与终局联系。终局相关筛选帮助聚焦候选，但最终裁决允许指向上游实例之外的步骤。

“触发证据”原样展示官方返回的错误承诺与被违反依据。原文引用支持原始消息跳转高亮；官方压缩视图引用可展开对应视图并高亮引用片段，通过“对照原文”查看对应消息。引用可定位到多个视图时保留位置选择；只有原始输入和官方视图都无法定位时才提示来源未定位。模型原始分类与解释保留原语言。

引用统计分别展示原文、压缩视图和未定位数量。来源定位只说明文字可追溯，不表示摘要含义或诊断因果已经人工确认。

轨迹详情右侧默认打开「综合分析」中的「结论总览」。按下综合关键步骤可跳到原始轨迹。各引擎的候选置信度以高、中、低显示，人工复核状态单独显示。各路均未提供有效候选时，关键步骤区域提示暂无有效候选。可切换到本次运行的引擎页签核对原始结论和证据。需要调整诊断等级时，在任务详情选择「重新分析」。复制任务或重新分析会预选等效的当前等级，其余预选 Standard。

## 4. 人工复核与导出

确认、修改或驳回结论，并在复核说明中记录修复与验证计划。修改关键步骤时校验消息范围和诊断资格；驳回清空关键步骤。重新选择确认模型结论会恢复模型原始字段。

可在独立的「改进建议」页签为本条轨迹生成一份建议。Fast、Standard、Deep 均采用当前诊断结论与关键步骤原文。人工复核结论优先，采用暂定结论时显示待复核。建议包含改动内容和回归验证方式，可定位依据的关键步骤。未定位有效关键步骤时，先重新诊断或人工复核。可重试失败请求、重新生成或导出。旧版 TrajDebug 建议仍可查看、复制和导出。

导出 Markdown（当前复核结论、模型原始结论、证据、生命周期、已生成建议与用量）、完整 JSON、官方最终原始 JSON，或独立的改进建议 JSON。人工复核和建议均独立于原始诊断保存。

## 5. 按 Agent 制定任务改进计划

在任务详情打开「任务改进建议」，点击「生成改进建议」。系统按轨迹列表中的 Agent 汇总同组轨迹的失败证据。建议包含优先级、建议改动和回归验证，可点击证据链接回到轨迹对应步骤。

报告展示最新建议、纳入数量、代表证据数量，以及待复核、缺少原文或轨迹的 Agent 未识别等未纳入原因。每组使用至多 12 条代表轨迹，建议上的证据数量表示可点击核对的样本数。同一证据范围重试时，已完成的 Agent 分组可复用。

## 返回路径与持久化

工作台的顶部和导航保持在视口内。任务列表、任务内轨迹和轨迹库在表格内滚动，表头固定在表格顶部，分页在表格下方。窄屏和较矮的窗口可按需展开任务概览，窄且矮的窗口可按需展开筛选与批量操作。新建任务和系统设置各自在表单或设置区域滚动。轨迹详情的执行记录、引擎结论列表和改进建议内容分别滚动，关键步骤入口留在对应区域顶部。窄屏通过页签切换，点击诊断证据会打开对应的执行步骤。

单条详情使用任务的当前诊断。上一条和下一条遍历筛选范围，支持跨页。返回任务时保留筛选、每页条数与所在页，并标记当前轨迹。刷新后数据、请求历史与复核来自 SQLite，页码和筛选来自 URL。

从单条详情导出 Markdown、完整 JSON、官方最终输出或已生成反馈；从任务列表导出整轮或所选轨迹 JSON。导出保留每次请求、原始模型结果和人工记录。

没有任务时引导新建；未配置模型可先保存已校验数据为草稿。

## 系统设置

「诊断分析模型配置」管理新任务使用的默认模型。添加或编辑单个诊断模型时，可设置轨迹并发、模型请求并发、重试、超时、输出上限和聚类 JSON 模式。运行参数可在模型列表中展开查看。环境配置可以编辑运行参数，连接信息由环境变量提供。

「Playground 模型配置」可独立保存、测试和设置默认模型。左侧的「Playground」和「诊断知识库」是轨迹回放与诊断知识接入的预留入口。
