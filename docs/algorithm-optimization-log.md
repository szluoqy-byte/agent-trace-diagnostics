# TrajDebug 算法优化维护日志

这份日志记录工作台在固定 TrajDebug 官方算法基础上进行的每次准确率优化。每项修改都需要记录代码位置、适用阶段、离线验证结果、是否启用和回滚依据。

## 固定基线

| 项目 | 固定值 |
| --- | --- |
| 官方仓库 | `https://github.com/THU-KEG/TrajDebug` |
| 官方提交 | `5b04f98b1995ec758d9aba70940d17bb7d2d169b` |
| 官方阶段 | Stage A 压缩、Stage B 触发、Phase 1 聚类、Phase 2 生命周期、Phase 3 关键失败归因 |
| 主要指标 | 关键失败步骤精确命中率 |
| 选择流程 | train 设计候选、dev 筛选、heldout 和 external_eval 验收 |
| 防过拟合约束 | 按任务组等权，分区之间不共享任务组，留出集和跨域集只在候选冻结后揭盲 |

官方源码位于 `backend/tracelens/_vendor/trajdebug/`，哈希清单位于 `UPSTREAM.json`。优化代码应优先位于适配层、报告层或独立后处理模块，避免直接修改官方阶段实现。

### 多引擎关键步骤投影（2026-11-27）

- 涉及 `backend/tracelens/diagnosis/synthesis.py` 的工作台综合选步，以及任务列表、详情、复核和导出读取的步骤。TrajDebug 原始诊断作为候选来源。
- 将旧的 `insufficient` 归为低置信度。按步骤比较各等级支持，完全并列时采用主引擎候选或较早的并列候选。综合评估失败时用完成的引擎结果选步。
- 后端回归验证了 `#3 高 / #2 证据不足 / #2 高` 选择 `#2`，并覆盖同分、综合失败、仅一路完成和范围校验。未重跑 RSI 数据集。
- 回滚时还原工作台投影、综合提示词和相应展示，并保留已保存的引擎原始报告。

### 综合分析同分裁决与 CHIEF 结果投影（2026-11-27）

- 保留代码排序。有效候选完全并列时，仅采用当前综合模型返回且通过原文校验的推荐。该推荐复用同一次综合请求。
- CHIEF 最终编号缺失或越界且最终引文唯一匹配原有候选时，适配层依据引文定位。候选阶段的置信度在 CHIEF 详情中单独展示，评分达到 0.8 为高，达到 0.5 为中，其余为低。
- 回归覆盖模型推荐的采用和拒绝、任务列表和导出投影、CHIEF 引文唯一匹配与歧义场景。回滚可还原适配层和综合选步逻辑，已保存的原始引擎报告可继续使用。

## 第一轮阶段诊断

第一轮 200 条精简集的完整结果记录在 [第一轮 RSI 阶段分析](rsi-round-1-analysis.md)。当前优先级如下。

1. 减少官方已触发样本在 Phase 1 对 `origin_step` 和 `qualified_origin_step` 的偏移
2. 改善 Phase 3 在多个合法实例之间的最终选择
3. 对 Stage B 原生漏检只保留经过 Phase 1–3 端到端验证的候选
4. 继续验证跨域数据，避免只改善航空和零售内部样本
